# 第三版：作品存储、上传与安全加固方案

最新状态（2026-10-16）：主体上传/管理/隔离功能已本地实现和联调，云端 SFTP 与 IP 证书/续期设施已配置，应用尚未发布。COS 深查发现现有挂载为 HTTP + `public_bucket=1` 匿名模式，匿名桶根 200、私有 marker 403；角色元数据 404。需要先完成私有权限和访问身份，再进行真实 COS 导入/发布。此前“私有存储”来自用户描述，下面的初查、待做和未实施段落保留为历史方案，不能作为当前验收事实。详见 [最新进度](v3-progress.md)、[COS 配置](v3-cos-access-setup.md)、[操作说明](v3-owner-guide.md)。本站实际前缀为 `syyh-site/`，SFTP 目录为 `/var/lib/syyh-sftp/inbox`，当前上传为每文件 raw octet-stream（不使用 multipart），应用与 Nginx 上限均为 30MiB。

原方案日期：2026-10-15；挂载初查：2026-10-16（北京时间）。

## 1. 建议采用的方案

**日常使用浏览器 HTTPS 管理作品，SFTP 作为批量导入与应急通道；作品文件保存在私有对象存储，Docker 从宿主机 `/datastore` 的本网站子目录只读供图；作品元数据、会话和队列数据库留在服务器本地持久卷。**

用户已说明：服务器挂载私有对象存储到 `/datastore`，用于所有作品；2026-10-16进一步确认提供商为**腾讯云 COS**。随后经只读SSH核验：`findmnt -T /datastore`显示来源`cosfs`、类型`fuse.cosfs`，选项含`rw,allow_other`，`stat`显示挂载根为`root:root`、权限`777`。这仅证明当前主机挂载状态，不证明桶/对象接口的真实授权范围；实际存储桶、地域、本站独立前缀、进程访问与对象接口身份尚未核验。本方案不把对象挂载视为完整 POSIX 本地磁盘，也不假定整个 `/datastore` 只属于本网站。宽松的本机挂载可见性与权限须在共享用途核对后收紧，不能直接把整处挂载暴露给容器或网站。

| 项目 | 本轮源码可确认的现状 | 第三版需要改变的部分 |
|---|---|---|
| 生产服务 | `web` 静态 Nginx + `api` Fastify；API不映射公网端口 | 增加管理认证、上传与动态作品数据；继续由边缘代理承接公网 |
| 文件挂载 | Compose 仅有留言卷，没有 `/datastore` 挂载 | 在确认的网站前缀内增加只读作品挂载与健康检查 |
| 请求限制 | Nginx全局 `8k`，Fastify全局4096字节 | 上传接口单独支持30M级媒体；留言等接口保留小限制 |
| 内容发布 | Next静态导出，作品详情路径在构建时预生成 | 新作品发布后无需改源码、重建Docker镜像；支持新增URL及分享信息 |
| 公网管理 | 当前API没有登录或作品管理接口 | 认证在服务端逐请求执行，不能依赖隐藏地址或前端判断 |
| 安全基线 | Nginx有部分安全头，未配置本项目TLS/CSP；安全头存在继承覆盖风险 | 把HTTPS、会话、文件隔离、响应头、最小权限、恢复演练列为发布条件 |

以上含源码检查与上述三项只读挂载查询，不是公网安全审计；没有扫描线上服务或修改服务器。

## 2. 本地如何上传

| 通道 | 站主怎么操作 | 服务器怎么处理 | 定位 |
|---|---|---|---|
| **HTTPS 管理界面** | 登录站主入口，选择图片/视频，填写标题与分类，查看进度，预览后发布 | 经认证后流式接收，进入校验/处理/持久化流程，默认草稿 | 日常默认方式；电脑和手机均可使用 |
| **SFTP** | 用SSH密钥将文件批量传入专用待导入目录，可附作品清单 | 导入器经同一校验流程生成草稿，管理界面补信息并发布 | 批量导入、网络不稳时传文件及应急；不直接改公开内容 |
| 对象存储客户端/浏览器直传 | 后续如确有大文件需求再设计短期、限前缀上传授权 | 仍须服务端核验并确认入库 | 当前30M级文件不作为默认方案；不向浏览器下发长期存储密钥 |

HTTPS与SFTP解决的是传输，**传完文件不等于作品已发布**。标题、分类、封面、顺序和发布状态由作品记录管理。SFTP使用SSH加密与主机身份校验，和FTP是不同协议。[OpenSSH SFTP手册](https://man.openbsd.org/sftp.1)

### 日常操作流程

1. 通过受信任证书的HTTPS站主入口登录；访客直接浏览公开站。
2. 新建作品，选择 Her 她的故事 / ZZZ 绝区零二 / FFF 关于未来 / COS 次元冲突，填写标题与简介。
3. 上传封面、图片或视频；界面区分传输进度、校验/处理状态、成功和失败。
4. 文件全部通过后保存草稿；登录状态下预览。
5. 点击发布，将已验证的完整版本公开；修改素材生成新版本，准备完成后再切换。
6. 撤下后公开页面和接口不再提供该作品；文件保留用于恢复及受控清理。

单文件上限沿用用户填写的“30M以内”。建议配置统一采用30MiB，即31,457,280字节，并在界面明确；这属于待定实现口径，不擅自视为用户已确认。Nginx上传请求可预留multipart开销，例如32MiB，服务端仍严格校验单文件上限。分文件上传，不一次将整套作品全部读入内存；限并发、磁盘配额和处理耗时。原留言接口不因此放宽到几十MB。

### SFTP导入规则

- 专用上传账户使用SSH密钥；限制到本地待导入区，无sudo、Docker组、交互式shell或端口转发权限。客户端核对SSH主机指纹。
- 待导入区放本地磁盘，例如 `/var/lib/syyh-upload/inbox`，不直接暴露为网站路径。大批量素材可分批导入，目录配额单独控制。
- 不读取仍在传输的半文件；采用完成标志或人工点击“导入”。若用重命名标记完成，仅在本地磁盘执行，不依赖对象挂载上的原子rename。
- 复用HTTP上传的类型、大小、内容与权限规则；清单仅作为数据解析，禁止执行脚本。重复导入可识别并重试，不自动生成重复公开作品。
- 管理口令与SSH密钥分开；SFTP不是绕过发布审核和文件限制的后门。

## 3. 私有对象存储与Docker如何配合

推荐目录布局，实际前缀在核验后确定，不迁移或修改其他项目数据：

```text
对象存储（保持私有） → 宿主机 /datastore
  /datastore/syyhsite/
    originals/<asset-id>/<revision>/...  原始文件，默认仅站主
    derived/<asset-id>/<revision>/...    网页图片/视频，仍由发布状态控制访问
    manifests/...                       文件、来源、校验值和版本记录
    backups/...                         数据库快照等备份归档

服务器本地磁盘/持久卷（不放在上述对象挂载内）
  作品数据库、会话、任务队列、现有留言数据库
  上传暂存、图片处理、SFTP待导入区、有限容量的缓存
```

“私有”指对象桶不允许匿名列目录和直接读写；发布后的网页版本由网站授权提供给访客。目录名叫 `derived` 并不表示可以整体公开。默认不公开原文件下载，是否增加该功能另按站主决定；之前填写“无存储约束”不等于授权公开所有原图。

### 读写权限与发布一致性

1. **持久写入优先走存储提供商官方对象接口**，使用服务身份或仅限本站前缀的凭据。保留 `/datastore` 供Docker读取；这样上传完成状态不依赖将FUSE挂载当成本地文件系统。如果只能通过挂载写入，先验证驱动的close、失败、可见性和恢复语义，再启用兼容路径。
2. 文件先写本地暂存，校验后上传为新对象键，不原地覆盖已发布文件。记录服务端SHA256、大小、类型和来源；完成校验后再更新数据库指针，不依赖对象目录rename实现原子发布。
3. 对象接口成功还不等于实际供图路径可读：须检查Docker看到的挂载路径，处理驱动缓存/可见性延迟，失败保持草稿或处理中，不提前公开半成品。分片ETag不能直接当作文件MD5。
4. 只给供图容器挂 `derived` 子目录且只读；前端渲染服务不持有对象存储写凭据。API/受限处理进程按需访问原图，凭据不进镜像、Git、网页或日志。
5. 文件归档使用版本化对象键；删除作品先撤下和解除引用，过期文件由受控清理处理，避免删掉仍被引用的素材。运行账户不授予桶管理或永久删除历史备份的权限。

拟议Compose挂载片段，**仅用于说明，不是可直接替换现有部署的完整配置**：

```yaml
services:
  edge:
    volumes:
      - type: bind
        source: /datastore/syyhsite/derived
        target: /srv/works
        read_only: true
        bind:
          create_host_path: false
```

Docker的只读bind mount适合限制容器写入宿主文件，但不等于作品访问授权；访问控制仍由应用执行。[Docker挂载文档](https://docs.docker.com/engine/storage/bind-mounts/)

### 挂载故障必须有明确定义

- 启动前检查真实挂载类型、本站标记和可读性；不能只判断目录存在，否则挂载失败时可能误写宿主机空目录。
- `/datastore` 在宿主机先挂载，供图容器随后启动；不为读取现有挂载而给容器 `privileged`、宿主Docker socket或额外FUSE管理权限。
- 只调整本站前缀所需UID/GID或ACL，不对整个 `/datastore` 执行递归chmod/chown。FUSE用户映射及可读权限按实际工具核验。
- 挂载丢失时停止上传发布并返回明确的存储不可用状态；不能将整个作品库误判为空并覆盖记录。健康检查和告警区分API存活与存储可用。
- Docker默认挂载传播不能保证宿主机卸载/重挂后自动恢复容器视图。需测试重挂场景并重建受影响容器，或制定与实际挂载服务匹配的依赖/传播配置，不盲目使用共享挂载。

### 数据库不放 `/datastore`

作品记录、发布状态、会话、队列及SQLite WAL放本地持久卷，原留言卷保留。只将一致性数据库快照归档到对象存储。SQLite WAL依赖共享内存与文件系统协调，官方说明不支持网络文件系统；对象挂载未经证明不应作为运行数据库盘。[SQLite WAL文档](https://www.sqlite.org/wal.html)

## 4. 访客如何读取作品而不看到草稿

建议路径：**浏览器HTTPS → Nginx → API检查作品/素材发布状态 → Nginx内部供图路径 → 只读挂载文件**。

- 公开作品接口只返回已发布且素材就绪的版本。媒体请求也按asset ID查询授权关系，不能只保护列表而让原文件路径可猜到。
- API批准后使用Nginx内部转发（如 `X-Accel-Redirect`）处理文件与视频Range；内部路径禁止外部直接访问，不把整个 `/datastore` 配成公开alias。
- 原图与草稿走站主认证读取；访客即使知道ID、原始文件名或内部URI也不能获取。文件真实路径由服务端记录生成，拒绝目录穿越及导入符号链接。
- 草稿、预览、管理接口及原图使用 `no-store`。首版公开作品媒体先采用需重新验证的缓存策略，源站每次授权后再处理304/Range，避免缓存绕过撤下；以后接CDN时增加明确失效机制。
- 已经被访客下载的公开内容无法远程收回；撤下控制后续网站提供行为。

## 5. 发布后无需重新打包镜像

作品不再写死在源码或COPY进Docker镜像。当前 `output: export` 和 `generateStaticParams` 无法自然产生上传后的新详情路径。

**建议第三版采用Nginx边缘代理 + Next运行服务 + Fastify内容/留言API的三个常驻服务**：作品详情、标题/分享信息读取运行数据；其他页面保留可静态优化的部分。Next和API均不单独映射公网端口。若最终选择受控内容生成方案，仍须满足新增URL、正确404、分享信息、缓存失效及“站主不执行构建命令”的同一验收标准。

这是本轮技术建议，尚未改变技术栈或增加容器。上线前在现有服务器资源上实测，媒体处理限制并发，必要时独立受限处理进程，不默认引入额外缓存数据库。Next官方也建议自托管时由反向代理承担请求和限流等保护。[Next自托管文档](https://nextjs.org/docs/app/guides/self-hosting)

## 6. 安全加固：本版发布条件

目标覆盖传输篡改、站主会话窃取/接管、恶意上传、未授权素材读取及生产数据破坏。HTTPS保护传输，仍需认证、脚本和服务器权限共同配合，不能据此承诺绝对不会被劫持。

| 范围 | 本版必须落实 | 对日常使用的影响 |
|---|---|---|
| HTTPS与域名 | 受信任证书、自动续期、全站HTTPS与HTTP跳转，无混合内容；验证稳定后启用HSTS；域名/DNS管理账号开启MFA，未配置域名不指向未知服务 | 访客正常打开网站；站主公网管理仅走HTTPS |
| 站主认证 | 保留单站主口令登录，强口令经Argon2id等合适算法哈希；登录按账户与来源限流，不因单一IP变化就封锁合法移动用户；恢复与注销全部设备可用 | 口令不进URL或前端存储；异常尝试有明确反馈 |
| 会话防窃取 | 随机服务端会话、登录后换ID、可撤销；`Secure` / `HttpOnly` / `SameSite=Strict`，优先host-only `__Host-` cookie；空闲与绝对有效期在服务端执行 | 不要求每次上传重复登录；长上传的会话续期与失败恢复有设计 |
| 管理隔离 | 推荐公开域名 + `admin`子域名，host-only cookie；两者所有管理写操作仍有CSRF token与精确Origin检查，不依赖SameSite保护兄弟子域 | 一个域名下的两个入口，访客不用登录；后台地址本身不充当密码 |
| 跨站与脚本 | 公共/站主Host白名单，严格来源和代理头边界；不放开任意带凭据CORS；简介按文本、Story富文本按白名单清理；CSP先Report-Only后强制，hash/nonce与实际渲染模式匹配 | 正常导航、主题、原画/3D/视频需在CSP下验证 |
| 上传与处理 | 图片/视频允许列表、服务端大小/签名/真实解码验证，生成随机存储名；不接受HTML/SVG/脚本/压缩包作为公开媒体；限制像素、帧数、时长、并发和耗时；派生图片移除非必要元数据 | 上传不合规时给可理解的原因，原图可保留于私有区 |
| 响应头与缓存 | 修复Nginx安全头继承，覆盖HTML、JS、媒体和错误响应；nosniff、防嵌入、Referrer/Permissions策略；管理/草稿不缓存，撤下不得被代理缓存绕过 | 对访问透明；需要实测304/404/413/429/5xx |
| 主机与容器 | 非root、只读根文件系统、最小可写卷、去除不必要capability、no-new-privileges、资源上限；仅边缘入口暴露80/443，SSH密钥管理并限制来源，API/数据库不公网暴露 | 访客无需VPN；站主可选额外私网入口 |
| 数据与运维 | 原图/派生物/作品记录版本关联，数据库一致性快照、独立副本、恢复演练；登录/发布/撤下审计，敏感字段不记日志；证书、挂载、存储配额、备份失败有告警 | 作品更新可回退；旧留言和历史源文件保留 |
| 供应链 | 锁定运行版本与依赖，检查生产依赖和镜像漏洞；处置可利用高危项，记录固定版本与实际验证范围 | 更新以兼容和可恢复为前提，不盲目全量升级 |

会话、CSRF与上传细则依据OWASP官方指南；具体超时/限流数值在实现时按单站主和真实网络条件校准，不套用一个全站限流值。[会话](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)、[CSRF](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)、[上传](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)

### 便利性与进一步的账号保护

站主仍可使用口令入口。**建议增加Passkey第二因子，或TOTP作为替代**，重点保护新设备登录、改口令/恢复方式等敏感操作；启用方式及恢复体验在管理界面评审时决定，不把用户已选口令登录擅自改成依赖第三方账号。日常不默认弹验证码，也不使用长期开放的对象写入链接。[OWASP多因素指南](https://cheatsheetseries.owasp.org/cheatsheets/Multifactor_Authentication_Cheat_Sheet.html)

HSTS在证书/续期确认后启用；初期不直接加preload或覆盖未确认子域名。HTTPS证书入口未就绪前，公网HTTP预览不开放管理登录/上传；可先通过既有SSH/SFTP运维通道传入待导入区，并在本地/受控环境开发管理流程。若继续使用IP作为管理地址，需要另核验可用的受信任证书方案，不以忽略证书错误代替验证。[TLS指南](https://cheatsheetseries.owasp.org/cheatsheets/Transport_Layer_Security_Cheat_Sheet.html)
