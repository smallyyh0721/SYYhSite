# VISITOR ACCESS · 3D 人物需求与实施方案

状态：已澄清需求，具体人物形象后续设计；目前不制作人物图或模型，不开始网站搭建。本说明优先于 v1/v2 中把“3D 动画跟随鼠标”理解为岛屿镜头的表述。

## 明确的需求

位置是 **01 / VISITOR ACCESS 右侧人物区**。此处需要真正的 3D 人物，替代目前的线稿人物占位。保留左侧标题、昵称与进入按钮，以及右侧约 3:4 的人物展示区。角色的性别、脸型、服饰、配色和风格尚未指定，不将旧图中的耳机人物视为已选定形象。

岛屿旅行是另一套交互。四岛的概念设计保持有效；是否将四岛全部制作成真正 3D 世界仍是待选实施方式，并未由这次人物需求确定。

## 建议的人物反应

默认镜头固定，人物保持在右侧展示位。鼠标在入口页上下左右移动时：眼睛先看向指针，头部缓慢跟随，上身轻微转向；可叠加呼吸、眨眼等自然待机动作。暂不增加自动说话、复杂表情或点击动作。

跟随不是把整个角色平移到鼠标位置，也不是无界旋转。建议初始范围：头部左右约 ±15–20°、上下约 ±8–12°；上身约 ±3–5°。这些是待人物模型与实际观感验证的参数，并非最终锁定值。指针离开入口页时人物平滑回正。

昵称输入和主题按钮仍是 DOM 控件。可在入口容器监听 pointermove，让人物看向左侧表单；人物 Canvas 本身不拦截表单事件。主题切换只改变环境、主光与轮廓光，不改变人物形象。Day 用柔和蓝白灯光，Night 保持可见的面部补光与暗色环境。

手机无鼠标时以轻量待机为主，不要求跟手指持续转头；减少动态模式使用静止姿态。进入 Hub 后暂停并卸载或释放入口人物渲染，避免与世界渲染竞争资源。

## 技术方案

推荐 **Three.js + React Three Fiber + GLB/glTF 骨骼模型**。角色建模、拓扑、贴图、绑定在 Blender 或其他 DCC 完成，再导出网页资源。至少有头、颈、上身的可控骨骼；眼球可用骨骼/独立物体控制，眨眼按模型支持使用骨骼或 morph target。骨骼蒙皮可通过 [Three.js SkinnedMesh](https://threejs.org/docs/pages/SkinnedMesh.html)实现，GLTFLoader 加载导出的资源。

实现流程：

```text
入口区域鼠标位置
  → 归一化 x/y
  → 计算限幅的眼睛、头部、上身目标姿态
  → 按 dt 平滑插值
  → 更新模型骨骼
  → 固定镜头渲染人物
```

若仅需要“立体模型整体微转”，不一定需要骨骼；但“人物看向鼠标”的自然效果需要头/眼独立控制，因此建议资产阶段就准备绑定。

逐帧更新使用 R3F `useFrame` 和对象 ref，而非每帧 React setState，参考 [R3F 基础动画](https://r3f.docs.pmnd.rs/tutorials/basic-animations)。骨骼旋转使用本地姿态与四元数插值，保持模型原始轴向；待机动画先求基础姿态，再叠加跟随偏移，避免 AnimationMixer 和跟随逻辑反复覆盖同一骨骼。每帧只由一个 AvatarController 写最终姿态，不累积旋转偏差。

拟建模块：

```text
features/gate/avatar/
  AvatarCanvas          # 右侧透明 Canvas，镜头固定
  AvatarAsset           # GLB 加载与静态海报降级
  AvatarController      # 指针、待机与跟随姿态统一控制
  AvatarLighting        # Day / Night 人物灯光
  avatar-config         # 模型 URL、骨骼映射、角度限制、构图
```

## 后续设计与验收

先确定人物风格、形象和半身/全身构图，再出角色设计与建模参考；确认后建模和绑定，最后接入入口。旧入口线稿仅为布局占位，不提前为未确定角色绑定动作。

验收重点：看向左右/上下指针自然且有边界；输入时不遮挡控件；指针离开回正；待机与跟随不抖动；Day/Night 都看得清脸；手机和减少动态可用；模型加载失败仍能作为游客进入网站。
