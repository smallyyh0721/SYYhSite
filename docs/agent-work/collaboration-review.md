## 已解决反馈，供后续读取

**F01 / 元素与动作明确（P2-06）**
目标是h1文本WELCOME TO MY WORLD.、按钮CONNECT，两者居中；当时draft把标题写成CONNECT。Codex任务书把“欢迎页标题CONNECT居中”混写，Grok按文字执行又未消解源码冲突。Codex承担歧义责任。下次分别写h1/button文本、位置、显示时机和旧/新行为；Grok复述发现冲突就交lead澄清。验收分别读取标题、按钮及中心坐标，不只查CONNECT存在。

**F02 / 并发快照与发布事实（P2-02/P2-06）**
核心/图片同时由Codex写入，Grok读到旧状态，文案又按目标写。Grok明确标注读取时刻和未测项，这是正确的；Codex需提供基线SHA和依赖状态。独立组件先写，事实文案待依赖完成后核对。报告区分目标/源码快照/已验证，完成时diff、页面、报告三者一致。

**F03 / 完整规则链（P2-08）**
当时仅看背景reduce规则，推断岛漂浮不取消；实际globals对元素/伪元素设置animation:none!important。下次同时查局部CSS、globals、Theme与父状态；未查完整就限定结论。验收列规则来源并看computed style/运行状态；视觉结论另目检。

**F04 / 暂停与降级分别设计（P2-08）**
把暂停/后台/reduce/失败都换poster会导致暂停跳图。暂停与后台冻结当前帧，reduce/失败/弱设备才选poster；恢复按状态处理。验收画面连续、失败仍可进入、恢复不重复跳转。

**F05 / 可复跑证据（P2-06）**
Grok报告326项开发态断言与临时截图；Codex不以断言总数代替生产验收。旧任务书未开放证据目录，临时产物符合当时限制。下次Codex开放脚本/证据目录；Grok给关键流程、主题/尺寸矩阵、准确命令和截图，批量断言数作补充。Codex可复跑且保留失败/未验证记录。

**F06 / 产品文字与开发报告（P2-06）**
访客需要“本站设计研究、真实作品待补”等事实；内部归属/验收过程放报告。下次页面以访客能理解并行动的内容为准，draft可列真实缺口，不能编造身份/项目。
